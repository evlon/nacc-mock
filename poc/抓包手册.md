# 抓包手册：获取 POC 所需的运行时参数

> 静态逆向已经还原了协议**结构**（路径、参数名、加密算法、明文格式），
> 但以下**运行时具体值**必须在真实环境抓包确认，否则 POC 无法跑通。

---

## 一、需要抓包确认的 4 类参数

| # | 参数 | 为什么静态拿不到 | 抓包方法 |
|---|------|-----------------|---------|
| 1 | 服务器地址/端口 | Setup.ini 里是 `0.0.0.0` 占位符，真实值在已装客户端注册表 | 查注册表 或 抓 HTTPS 连接目标 |
| 2 | sessionid/pskey 的响应字段名 | 逆向只看到"读注册表 pskey"，字段名在服务器响应里 | 抓登录响应的 body |
| 3 | AES-192 密钥派生方式 | pskey 字符串 → 24 字节密钥的确切映射 | 抓上报请求 + 本地复算比对 |
| 4 | EAP 方法 + 报文格式 | 交换机用 EAP-MD5/PEAP/TLS？挑战字段偏移 | 抓 EAPOL 包 |

---

## 二、具体操作步骤

### 步骤 1：查服务器地址（最简单）

在**已装客户端的合规机器**上：

```
reg query "HKLM\SOFTWARE\NACC" /v ServerAddress
```

或者用 PowerShell：

```powershell
Get-ItemProperty "HKLM:\SOFTWARE\NACC" | Select-Object ServerAddress, sessionid, pskey, user_name
```

把 `ServerAddress` 填进 `nac_client_poc.py` 的 `CONFIG["server"]`。

---

### 步骤 2：抓登录响应，确认 sessionid/pskey 字段

在合规机器上用 Wireshark 抓包（filter: `tcp port 443`），或用 mitmproxy 解密 TLS：

```bash
# 方法 A：Wireshark + 服务器私钥（若环境提供）
# 方法 B：mitmproxy 透明代理 + 导入 CA（推荐，能直接看 HTTP body）
mitmproxy -p 8080
# 让 NACC.exe 走代理（或网关重定向），观察 POST /nac/user/auth/password 的响应
```

登录成功后，响应里会包含 sessionid 和 pskey。记录它们的**字段名和格式**，
回填 `nac_client_poc.py` 的 `login()` 函数里的解析逻辑。

---

### 步骤 3：确认 AES-192 密钥派生方式（关键！）

这是 POC 最容易卡住的地方。逆向结论是「密钥=pskey，AES-192(24字节)」，
但 `pskey 字符串 → 24 字节` 的确切映射有几种可能：

- (a) pskey 是 24 字符 ASCII，直接取 UTF-8 字节
- (b) pskey 是 hex 字符串（48 字符），decode 成 24 字节
- (c) pskey 经过某种派生（hash/截断/补齐）

**验证方法**：
1. 抓一个真实的 `/nac/dev/check/helper?username=..&value=..` 请求，拿到 `value`（Base64 密文）
2. 用你从注册表读到的 sessionid + pskey + autologin_flag，按 `_derive_aes192_key` 的三种方式分别加密
3. 看哪种结果与抓到的 `value` 一致，即确定派生方式

---

### 步骤 4：抓 EAPOL，确认 EAP 方法

在树莓派直连交换机的网卡上抓 802.1X 报文：

```bash
# 抓 EAPOL（ethertype 0x888e）
sudo tcpdump -i eth0 -s0 -w eapol.pcap 'ether proto 0x888e'
# 或 Wireshark filter: eapol
```

用 Wireshark 打开，看交换机发来的 **EAP-Request 的 Type 字段**：

| Type 值 | 方法 | POC 实现难度 |
|---------|------|-------------|
| 4 | EAP-MD5 | 简单（已实现，可离线爆破密码） |
| 25 | PEAP | 中等（需 TLS 隧道 + 内层 MSCHAPv2） |
| 13 | EAP-TLS | 难（需设备证书，本系统无客户端证书，不太可能） |

**这套系统大概率不是 EAP-TLS**（安装包无 .p12/.pfx/.pem 客户端私钥），
所以很可能用 EAP-MD5 或 PEAP。抓包确认后，在 `eapol_sim.py` 里补全对应分支。

---

## 三、一个关键前提确认

**先确认你们环境是否真的开了 802.1X**：

```powershell
Get-ItemProperty "HKLM:\SOFTWARE\NACC" | Select-Object EnableDot1X
```

- `EnableDot1X = 0`：默认纯终端侧拦截，**没有交换机 802.1X**，POC 只需做「登录+上报」（HTTP 部分），不需要 EAPOL。
- `EnableDot1X = 1`：才需要完整做「登录+上报+模拟EAP」。

---

## 四、POC 运行清单

1. 树莓派装依赖：`pip install requests pycryptodome scapy`
2. 按本手册填 `CONFIG`
3. 先跑 HTTP 部分（登录+上报）：
   ```bash
   python nac_client_poc.py
   ```
4. 若开了 802.1X，再跑 EAPOL 模拟：
   ```bash
   sudo python eapol_sim.py eth0 <用户名> <密码>
   ```
5. 验证：看交换机端口是否从"未认证"变为"已认证"，树莓派能否出网。
